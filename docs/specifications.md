# エディタ仕様・機能一覧

本ドキュメントは、Planetext エディタに実装されている全機能、操作仕様、編集機能、表示機能、巨大ファイル処理アーキテクチャ、検索アルゴリズム、下書き自動保存、文字コード・改行コード対応、およびショートカットキーの完全な一覧です。

---

## 1. エディタ基本仕様 & 画面レイアウト

- **行指向構造 + 二次元数式の統合**:
  - 本文は高速な行指向テキストモデルとして保持され、行内に分数・平方根・添字・行列などの二次元構造ノード（`NodeKind`）が兄弟要素として自然に並びます。
- **レイアウト密度 & タイポグラフィ**:
  - 行間: `line-height: 1.5`（画面内の行密度を最適化）
  - フォントウェイト: `font-weight: 400`（細身で鮮明なレギュラー表示）
  - フォントスタック: `"Segoe UI", "Yu Gothic", "Meiryo", "Hiragino Sans", "Noto Sans JP", sans-serif`
- **プロポーショナルフォントでのタブ列揃え（Column Alignment）**:
  - 行内に `Tab` を挿入することで、等幅フォントでなくても連続する行の同一タブ列が縦にピタリと整列します。
- **ガター変更バー & Overview Ruler**:
  - **ガター変更バー**: 編集された行のガター（行番号の右端）に、VS Code風の緑色の縦ラインがリアルタイム表示されます。
  - **Overview Ruler**: スクロールバー内部に、ドキュメント全体の変更行（緑色バー）および検索ヒット箇所（黄色マーカー）がミニマップとして投影されます。

---

## 2. 画面分割 & マルチペイン (Split-Pane & MVC)

- **ペイン分割**:
  - 左右への画面分割（2分割・3分割以上）に対応。
  - ショートカット `Ctrl + \` またはメニュー「表示」→「左右に分割」。
- **MVC 状態分離**:
  - ドキュメント本体（`Document` = Model）と表示画面（`Session` = View）が完全に分離。
  - 同一ドキュメントを複数ペインで同時に開き、互いにリアルタイム同期しながら独立したスクロール・カーソル位置で閲覧・編集可能。
- **タブのドラッグ＆ドロップ**:
  - タブバー内での並び替え、およびペイン間でのタブ移動に対応。
  - コンテキストメニューから「右のペインへ移動」「新しいペインへ分割」が可能。
- **入力連動グループ**:
  - `Alt + クリック` で複数ペインを同一入力グループに束ね、1つのキーストロークを複数ペインへ同時配信可能。

## 3. カーソル・選択操作 (Selection & Navigation)

- **ダブルクリック（単語選択）**:
  - **日本語形態素解析**: ブラウザの `Intl.Segmenter` を活用し、送り仮名を含む動詞（例: 「開ける」「取り組む」）や複合語を1単語として正確に選択。
  - **カタカナ連続語句の優先選択**: 長音符「ー」や中黒「・」を含むカタカナの連続（例: 「プレーンテキスト」「ユーザー・インターフェース」）を最優先でひとかたまりとして全体選択。
  - **英数識別子**: アンダースコアを含むプログラミング識別子（例: `calculate_tax_total_123`）を全体選択。
  - **数式構造内スロット**: 分母・分子・根号内などのスロット内でも同様に単語単位で選択。
- **トリプルクリック（行全体選択）**:
  - 3回連続クリックで、該当行全体（`0..line_len`）を選択。
  - 数式構造内部をクリックした場合は、そのスロット全体を選択。
- **キーボード範囲選択**:
  - `Shift + 矢印キー（Left / Right / Up / Down）`: キャレット位置を起点に文字単位・行単位で選択範囲を伸縮。
  - `Shift + PageUp / PageDown`: ページ単位での範囲選択。
  - `Shift + Home / End`: 行頭・行末までの範囲選択。
  - `Ctrl + Shift + Home / End`（または `Ctrl + Shift + Up / Down`）: ドキュメント先頭・末尾までの範囲選択。
- **マルチカーソル**:
  - `Ctrl + D`: 現在選択中の単語と同じ単語の次の一致箇所を追加選択。
  - `Alt + クリック`: 任意の位置にカーソルを追加配置。

## 4. 括弧の自動補完・ペア編集 (Bracket Automation)

- **自動ペア挿入**:
  - 開き括弧（`{`, `(`, `[`, `"`, `'`, `「`, `（`, `『`, `【`, `《`, `〈`, `〔`）を入力すると、対応する閉じ括弧が自動挿入され、キャレットが中央に配置されます。
- **選択範囲の括弧囲み**:
  - テキストを選択した状態で開き括弧を入力すると、選択範囲がその括弧ペアで囲まれます。
- **上書き入力（Overtype）**:
  - キャレットの直後に既に閉じ括弧がある状態で同じ閉じ括弧を入力すると、二重挿入されずに閉じ括弧を飛び越えます。
- **ペア削除（Backspace）**:
  - 空の括弧ペア（例: `(|)`）の間で Backspace を押すと、両方の括弧が同時に削除されます。
- **IME 2文字ペア入力対応**:
  - 日本語IME等で「かっこ」から変換して `【】` や `『』` などの2文字ペアを一括確定入力した場合にも、自動的にキャレットが2文字の中央へ移動します。

## 5. URL フォーカスツールチップ

- **URL 検知**:
  - キャレットが `http://` または `https://` で始まるURL文字列上にあることを自動検知。
- **コンパクトなアクションボタン**:
  - 行の上に `🔗 リンクを開く ↗` という小さく洗練されたボタンのみが浮かび上がります（マウスホバーで `title` 属性により完全なリンク先を確認可能）。
- **スクロール追従**:
  - マウスホイール、スクロールバー操作、矢印キー移動によるスクロール時にもエディタビューの再描画と同期し、ボタンがテキスト行の位置へ滑らかに追従（画面外へスクロールした場合は自動非表示）。
- **ブラウザ起動**:
  - ボタンをクリックすると、システムの既定のブラウザでURLを開きます。

## 6. ズーム・表示拡大縮小 (Zoom)

- **ショートカット**:
  - `Ctrl + Plus (+)` または `Ctrl + Equal (=)`: フォントサイズ +1px（最大 48px）
  - `Ctrl + Minus (-)`: フォントサイズ -1px（最小 9px）
  - `Ctrl + 0`: 標準サイズ（15px）にリセット
- **マウスホイール**:
  - `Ctrl + Wheel Up`: 拡大
  - `Ctrl + Wheel Down`: 縮小
- **行高さの自動再計算**:
  - フォントサイズ変更時に各ペインの行高さキャッシュ（`Heights`）を無効化し、全行の高さを即座に再計測してレイアウト崩れなく再描画。

## 7. 空白文字の可視化 (Whitespace Visualization)

- **トグル切り替え**:
  - `Alt + Z` キー、またはメニュー「表示」→「空白文字を表示する」でON/OFFを切り替え。
  - 設定ファイル（TOML形式）の `show_whitespace = true/false` に自動保存。
- **表示記号**:
  - 半角スペース（` `）: 中央の淡いドット（`·`）
  - 全角スペース（`　` / `\u{3000}`）: 全角幅に合わせた淡い矩形枠（`□`）
  - タブ文字（`\t`）: 列区切り位置に淡い矢印（`→`）
- **非干渉・非破壊設計**:
  - DOMテキストノード自体の文字コードや長さを一切改変せず、CSS擬似要素（`::before`）および絶対配置を用いて描画。
  - タブが存在する行でも行高さを押し広げず、選択範囲の計測やコピー操作にも一切影響を与えません。

## 8. 下書き自動保存 & セッション復元 (Drafts & Session Restore)

突然の電源断や誤終了からユーザーの未保存データを保護するための下書きシステムです。

- **自動デバウンス保存**:
  - タイピングを停止した少し後（非同期デバウンス）に、未保存のタブ内容・カーソル状態・ペイン構成をバックグラウンドで自動的にローカル下書き（`drafts`）として保存します。
- **シームレスなセッション復元**:
  - アプリを終了・再起動した際、前回開いていた未保存のタブやペインの状態が自動的に完全復元されます。
- **自動クリーンアップ**:
  - ファイル保存（`Ctrl + S`）が行われた時点で、該当ドキュメントの下書きは安全に消去されます。
- **巨大ファイル保護**:
  - 5 MB（`LARGE_BYTES`）を超える巨大ファイルについては、過剰なディスクI/Oと負荷を防ぐため、下書き自動書き出しを自動でスキップします。

## 9. 文字コード & 改行コード対応 (Encoding & Line Endings)

- **対応エンコーディング**:
  - `UTF-8`, `UTF-8 with BOM`, `Shift_JIS (CP932)`, `EUC-JP`, `ISO-2022-JP`, `UTF-16LE`, `UTF-16BE`
  - ファイルオープン時に文字コードを自動判別。ステータスバーから指定の文字コードで再読み込みまたはエンコード指定保存が可能。
- **改行コード対応**:
  - `CRLF` (Windows) / `LF` (Unix/Linux/macOS) / `CR` (Classic Mac) を自動判別し、保存時も元の改行コードを保持。ステータスバーから変換可能。

## 10. 数式・二次元構造の入力 (Formula & 2D Structures)

キーボードやパレット（`Ctrl + M`）から、直感的に二次元構造を入力・編集できます。

| 構造 | 入力操作 | 挙動 |
| --- | --- | --- |
| **分数（罫線とその上下）** | `1/` または `\frac` + スペース | 直前の連続文字列を分子として上に持ち上げ、分母スロットに入る |
| **平方根 / n乗根** | `\sqrt` + スペース、または `√` `√[n]` | 根号構造に入り、被開平数スロットに入る |
| **上付き / 下付き添字** | `x^` / `x_` + スペース | 直前の文字に対する上付き・下付きスロットに入る |
| **行列 / 連立方程式** | `\matrix` / `\cases` + スペース | 格子状スロットを生成。`&` で列追加、`Alt + Enter` で行追加 |
| **上下アノテーション** | 対象を選択して `Ctrl + ↑` / `Ctrl + ↓` | 任意の文字列・構造の真上／真下に小さい注記欄を開く |
| **構造スロット内移動** | `←` `→` `↑` `↓` `Home` `End` `Tab` | スロット間を移動（空のアノテーション欄は自動スキップ） |
| **構造の展開・削除** | `Backspace` | 中身のテキストを本文に残したまま構造枠だけを安全に展開 |
| **構造を抜ける** | `Enter` / `Esc` | 本文の通常入力に戻る（構造内では不用意に改行しない） |

## 12. 巨大ファイルの扱いと常駐管理アーキテクチャ (Large Files)

数ギガバイト・数千万行に及ぶ巨大ファイルであっても、メモリを圧迫せず瞬時に開いて編集するためのパイプライン設計です。

### 1. ゼロメモリ全文ロード（Zero-Whole-File-in-Memory）
- ファイルを開く際、全文をメモリにロードしません。
- 起動時は**先頭 1 MB のみを即座に読み込んで画面を表示**し、残りの改行数カウントと間引き索引（`STRIDE = 1024` 行ごとのバイトオフセット）の構築はバックグラウンドスレッドで非同期に実行します。
- 800 MB（1,600 万行）のファイルでも、Nativeプロセスの常駐メモリ消費量は約 70 MB に抑えられます。

### 2. ピーステーブル（Piece Table）による編集管理
- ドキュメントは `Piece::Saved(from_line, to_line)`（ディスク上の元ファイルを参照）と `Piece::Fresh(lines)`（ユーザーが編集・挿入した行）のピース列として保持されます。
- 巨大ファイルの一部を編集しても、ファイル全体のメモリ複製は発生しません。

### 3. 仮想窓（Virtual View Window）
- フロントエンド（wasm / webview）はファイル全体を持たず、**現在画面に見えている行＋上下バッファ（数十行）のみ**を `read_lines` で非同期に取り寄せて DOM に配置します。
- 1,000 万行のファイルであっても DOM ノード数は数十個で一定であり、スクロールや文字入力の描画負荷は数ミリ秒（60fps）を維持します。

### 4. 高速末尾ジャンプ（Fast Tail Read / Ctrl+End）
- バックグラウンドでの総行数走査の完了を待たずに `Ctrl + End` が押された場合、ファイルの EOF（末尾バイト）から逆方向に読み流して即座に末尾の窓を表示します。

### 5. 外部変更検知（External Modification Guard）
- ファイルの `mtime`（更新時刻）および `size`（バイト長）を監視し、エディタ外部でファイルが変更された場合は不正なシーク読み込みを防止して「開き直してください」と安全に通知します。

## 13. 検索エンジンと高速一致アルゴリズム (Search Engine & Benchmarks)

Planetext の検索エンジンは、巨大テキストに対してもメモリ帯域の理論限界に近い走査速度（数 GB/s）を達成するよう設計されています。

### 1. Boyer-Moore (BM) 法から近代方式への刷新経緯

- **BM法の限界**:
  - 古典的な Boyer-Moore (BM) 法は、スキップテーブルを用いた1バイト単位のシフトと後方照合を行います。
  - しかし現代の CPU アーキテクチャでは、**SIMD ベクトル命令**（AVX2 / SSE4.2 / ARM NEON）による並列走査（`memchr::memmem` の Two-Way / Needle pre-filtering）の方が、分岐予測ミスが極小であり、BM法と比較して **数十倍〜100倍以上高速** に動作します。
- **Unicode正規化（NFC/NFD）と多言語対応**:
  - 日本語の濁点・半濁点の結合文字（例: `か` + `\u{3099}` vs `が`）や全角/半角の違いがあるため、単純なバイトスキップテーブルでは一致漏れが生じます。

### 2. テキスト側正規化方式 vs クエリ側展開方式（Query Expansion）

検索の多言語正規化において、2つの方式のベンチマーク検証を行いました。

```
【方式1: テキスト側正規化方式】（不採用）
対象テキスト行を逐次 NFC 正規化 → 元の文字インデックスへのマッピング配列を作成 → 走査
・課題: 毎行ごとにヒープ確保（メモリ割り当て）と文字走査が発生し、走査速度が大幅に低下。

【方式2: クエリ側展開方式（Query Expansion）】（★採用）
検索クエリから事前に NFC版 と NFD版 のバリアントを生成
対象テキストは一切変換・コピーせず、生のバイト列のまま memchr::memmem (SIMD) で直接走査
・利点: ターゲットテキスト側でのメモリ確保が完全ゼロ、メモリ帯域上限（数 GB/s）で走査可能。
```

### 3. ベンチマーク検証結果（100,000 行・大規模走査）

`src/editor/search/matcher.rs` における 10 万行の実測ベンチマーク結果:

| 方式 | 処理時間 | スループット | メモリ確保 |
| --- | --- | --- | --- |
| **テキスト側正規化方式** | ~140 ms | ~0.2 GB/s | 毎行多数 |
| **クエリ側展開方式 (SIMD)** | **~2.8 ms** | **~8.5 GB/s** | **完全ゼロ** |

- **結論**: クエリ側展開方式は、テキスト側正規化方式と比較して **約50倍高速** であり、数百万行のファイルであっても瞬時に検索結果を返します。
- **注意（デグレ防止）**: 走査ループ内でターゲットテキストを文字列変換（`to_lowercase()` や `nfc()` 等）してメモリ確保を行わないこと。必ずクエリ側を展開し、テキスト側はスライスのまま SIMD 走査すること。

### 4. クエリ側展開方式のトレードオフ（混在ケース）と採用理由

クエリ側展開方式には以下の既知のトレードオフが存在しますが、性能と実用性の比較検討の上で意図してこの方式を採用しています。

- **既知の制限・トレードオフ（同一単語内でのNFC/NFD混在）**:
  - クエリ側展開方式では、クエリ文字列全体の「NFC一括版」と「NFD一括版」の2種類のバリアントを生成して走査します。
  - したがって、もし検索対象テキスト側で「1文字目はNFC（`が`）で、2文字目はNFD（`き`+`\u{3099}`）」のように、**1つの単語・文節の中でNFCとNFDが文字単位で入り混じっている（Mixed Normalization）** 極めて特殊なケースは検出できません。
  - これを網羅しようとすると、クエリ内の合成文字数 $N$ に対して $2^N$ 通りの全組み合わせバリアントが必要になり、クエリ生成コストと走査回数が指数関数的に爆発してしまいます。
- **なぜテキスト側正規化を行わず、このトレードオフを受け入れたのか（意思決定の根拠）**:
  1. **実世界での発生頻度**: 実際のファイルやOS（macOS HFS+由来のNFDファイル、Windows/Linux/Web標準のNFCファイル）では、ファイル全体または環境単位でNFCかNFDのどちらか一方に統一されています。同一単語の内部で1文字ごとに正規化形式がバラバラに混在するようなケースは、人工的なテストデータ以外では実用上ほぼ皆無です。
  2. **圧倒的なパフォーマンス差**: この極めて稀なコーナーケースを救うために「テキスト側正規化方式」を採用すると、巨大ファイル走査時に毎行のヒープ確保と文字ループが発生し、走査速度が **50倍低下（2.8ms → 140ms）** してしまいます。
  3. **設計判断**: 実用上ほぼ存在しない混在ケースのために常時50倍の速度ペナルティを払うのではなく、**実用上の99.999%のケースで最速スループット（数GB/s・メモリ確保ゼロ）を達成するクエリ側展開方式が最も合理的である**と判断し、本方式を採用しています。

## 14. 構文ハイライト & インライン補完 (Syntax Highlighting & Ghost Text Completion)

外部ランゲージサーバー（LSP）に依存せず、単一バイナリ内で完結する超高速・ゼロ遅延な構文ハイライトおよびインライン補完（ゴーストテキスト）機能です。

### 1. 組み込み対応言語 (初期 10 言語/フォーマット)
- **Rust** (`.rs`): キーワード、プリミティブ型、マクロ（`println!`）、ライフタイム、演算子
- **Kotlin** (`.kt`, `.kts`): `fun`, `val`, `var`, `suspend`, `data class`, `override`, 組み込み型
- **TypeScript / JavaScript** (`.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`): `interface`, `type`, `async/await`, `export` 等
- **Python** (`.py`, `.pyw`): `def`, `class`, `import`, 文字列（`f"..."`, `'''`）、`#` コメント
- **TOML / JSON** (`.toml`, `.json`): キー名、文字列、真偽値、数値、セクションヘッダー `[...]`
- **HTML / CSS** (`.html`, `.htm`, `.css`): タグ名、属性、セレクタ、プロパティ名、値、`<!-- -->`
- **Markdown** (`.md`, `.markdown`): 見出し `#`, リスト, リンク `[]()`, コードブロック ```` ``` ````
- **LaTeX** (`.tex`, `.latex`, および Markdown 内の `$ ... $` / `$$ ... $$`): `\begin{}`, `\frac`, `\alpha`, `\sum` コマンド及び数式記号

### 2. 拡張可能 & ユーザー定義可能な言語定義 (Extensible Language Definitions)
- 言語定義は純Rustの `LanguageDef` 構造体として定義され、ファイル拡張子または設定から自動解決されます。
- TOML 形式の言語定義ファイル（`name`, `extensions`, `line_comments`, `block_comments`, `string_delimiters`, `keywords`, `types`, `constants`, `builtins`, `operators`）を用意することで、ユーザー独自の言語や拡張構文を自由に追加・カスタマイズ可能です。

### 3. インライン補完（ゴーストテキスト / Phantom Text）
- **動作仕様**:
  - キャレット直前の入力単語（例: `pu`）をリアルタイムに検知。
  - キャレットのすぐ右側に、薄い半透明のグレー文字で残りの文字列（例: `blic`）がゴーストテキストとして表示されます。
- **補完候補のハイブリッド探索**:
  1. 言語定義辞書（キーワード・型・組み込み関数）
  2. 現在開いているファイル（バッファ）内に登場する識別子・変数名・関数名
- **キー操作**:
  - **確定挿入**: `Tab` または `Shift`（または `→` キー）を押すと、ゴーストテキストが一発で確定挿入されます。
  - **無視 / 切り替え**: そのまま別の文字をタイピングし続けると、自動的に次の候補に切り替わるか、一致しない場合はスッと消えます。
  - **キャンセル**: `Esc` を押すと一時的にゴーストテキストを非表示にできます。
