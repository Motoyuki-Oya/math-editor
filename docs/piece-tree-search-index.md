# ピースツリーと検索インデックスの連携

## 目的

巨大ファイルでも全文をメモリへ載せず、編集・行範囲の読み取り・検索・保存を行う。操作ログを唯一の履歴とし、ピースツリーと検索索引差分はそこから導出する。

## 座標

- 文書エンジン内部の正規座標は、文書のエンコーディングにおけるバイト位置とする
- Document Model からの編集は、revision 付きの行範囲置換として受け取る
- 検索結果など文書内の位置を返す公開界面は、revision 付きの行・列を使う
- Document は、受理した基準 revision 上で行範囲の境界をバイト範囲へ変換してから操作ログへ記録する
- ピースは絶対行番号を持たない
- B ツリーの部分木はバイト長と改行数を集約し、行位置を木の探索と対象付近の読み取りで求める
- 行数やファイルサイズに比例する位置変換を行わない
- 異常に長い 1 行は、既定の上限を超えた時点で開くことを拒否する

外部を行・列にしても、部分木の改行数から対象行を `O(log ピース数)` で絞り込み、列の変換は対象行内だけで行うため、巨大ファイル全体の走査は発生しない。

## ピースツリー

- B ツリーを使う
- ピースは、元ファイルまたは操作ログが所有する編集実体のバイト範囲を参照する
- 編集後の文書内容をピース内へ複製しない
- 編集では影響する経路のピースと部分木集約値だけを更新する
- B ツリーのノード容量は実行時の内部パラメータとし、初期値は 8 とする
- 木の再平衡は B ツリーの通常の挿入・削除処理として行い、別の再平衡処理を設けない

## 編集実体

- 挿入実体と、元ファイル参照では保持できない削除実体は、操作ログが所有する追記領域へ置く
- 挿入用と削除用の追記領域は分けてよいが、独立した履歴や別の真実にはしない
- 元ファイル由来の削除は、可能な限り元ファイルの範囲参照として保持する
- 操作量がメモリ予算を超えた場合は、同じ操作ログの永続領域へ流して参照へ置き換える

## 操作ログ

- 操作ログは、現在適用されている位置を持つトランザクション列とする
- 各トランザクションは、生成時点の基準 revision を持つ
- 各編集位置は、基準 revision 時点の内部バイト座標で記録する
- 古い revision を基準にした操作は、ログで現在座標へ写像してから原子的に適用する
- Undo/Redo はログの適用範囲を変更する
- Undo 後に新しい編集が入った場合は、その位置より後ろの Redo 枝を破棄する
- 単一編集、複数編集、規則的な一括編集を同じログで表現する
- 規則的な大量マルチカーソル編集は、編集位置を無制限に個別展開せず、基準 revision 上で再現可能な一括操作として保持する

ピースツリー、検索索引差分、下書き、Undo/Redo は、すべてこの操作ログから再構築可能でなければならない。

## 論理インデックスブロック

### 初期分割と現在サイズ

- 元ファイルを 512KB を目安に、文書のエンコーディングにおける文字境界で初期分割する
- 論理インデックスブロックの識別子は初期分割で決まり、編集後の現在位置によって振り直さない
- 編集後のブロックサイズは可変とする
- ブロックの開始バイト位置は保存せず、B ツリーの前方サイズ累計から求める
- 開始位置のメモ化は最適化として許容するが、正しさのための状態にはしない

### 肥大化したブロック

- 大きくなりすぎたブロックだけを、複数の実走査単位へ分割する
- 分割後の実走査単位は、分割前と同じ論理インデックスブロックに属する
- 分割しても、後続ブロックの識別子や開始位置を個別に更新しない
- 実走査単位は前後の単位と、所属する論理インデックスブロックを参照できる
- 分割閾値は実行時の内部パラメータとする

### ブロック境界

ブロック境界をまたぐ bi-gram は終了側の論理インデックスブロックへ数える。終了側を走査するときは、前のブロックの最後の 1 文字を重ねて読む。

## エンコーディング

- ピースツリーと編集実体は、文書のエンコーディングのバイト列を扱う
- 文字境界の判定と bi-gram の抽出で文書のエンコーディングを参照する
- 不正なバイト列は変更せず保持する
- 不正なバイト列を含む範囲は文字として解釈せず、bi-gram 索引の対象外にする
- 表示時の代替文字列から元ファイルを再構成しない
- エンコーディング変更と保存形式の判断は、ピースツリーの責務にしない

## 検索インデックス

### ベースと差分

- ベース索引は `(bi-gram, 論理インデックスブロック, 件数)` を持つ
- ベース索引は現在のベースファイルに対して構築し、編集中は書き換えない
- 編集による差分は、操作ログから導出する再構築可能なキャッシュとする
- 差分は `(bi-gram, 論理インデックスブロック, 正負のネット件数)` として集約する
- Undo/Redo では操作ログの適用範囲に合わせて差分キャッシュを加減算する
- 差分キャッシュを失っても、操作ログから再構築できる
- 差分キャッシュの集約と永続化はユーザー入力の idle 時に行う

件数推定は、ベース件数と差分キャッシュを足して求める。索引は候補絞り込みと概数推定だけに使い、ヒット位置は候補範囲の実走査で確定する。

### 編集境界

1 回の編集では、編集範囲の前後 1 文字を含む範囲について、編集前後の bi-gram を比較する。消えたものを負、新しく生じたものを正の差分として記録する。

## 下書きと保存

### 下書き

- 下書きは、ベース参照、操作ログ、操作ログが所有する編集実体、育てた索引を保持する
- 未保存状態は、ベースと操作ログを再生して復元する
- 保存中も、保存成功が確定するまでは操作ログを破棄しない

### 小さいファイル

- 保存後 Undo 用のベーススナップショットを保持できる
- 保存後も操作ログを保持し、Undo/Redo を可能にする

### 巨大ファイル

- 保存後 Undo 用のベーススナップショットを作らない
- 保存中はモーダルな進行表示を出し、対象文書への入力・Undo/Redo・再保存・文書を変更する操作を停止する
- 保存開始前までの操作をすべて文書エンジンへ反映してから保存する
- 最も前の編集位置より前の prefix は維持し、以降の元 suffix を退避する
- 保存ジャーナルに対象ファイル、対象 revision、変更開始位置、退避先、保存状態を記録する
- 現在のピースツリーから suffix を再構成して書き、結果を検証する
- 成功後に保存済みファイルを新しいベースとし、対象ブロックの索引差分を取り込み、操作ログと編集実体を破棄する
- 失敗またはクラッシュ時は、退避した suffix でベースを戻し、操作ログを再適用して未保存状態を復元する
- 保存の確定または復旧が終わった後に操作を再開する

### 文書を閉じるとき

文書を閉じた時点で、その文書の操作ログ、編集実体、保存後 Undo 用スナップショットを破棄してよい。開き直した文書は、保存済みファイルまたは下書きをベースとして新しい操作ログを開始する。

## 内部調整パラメータ

次の値はユーザー設定にせず、実装と計測で調整する内部パラメータとしてまとめる。

- B ツリーのノード容量（初期値 8）
- 論理インデックスブロックの初期サイズ（初期値 512KB）
- 実走査単位の分割閾値
- 索引を使用するファイルサイズの閾値（初期値 10MB 程度）
- 保存後 Undo 用スナップショットの上限
- 文書ストア全体のメモリ予算
- 入力 idle の判定時間
- 異常に長い 1 行の上限

モジュールの所有関係と Phase 4 以降からの利用方法は [文書エンジンのモジュール境界](document-engine-modules.md) を参照する。
