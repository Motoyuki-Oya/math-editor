# 編集コアのリファクタ方針

## いま何が起きているか

エディタは内部で **2 つの別々のエディタ** を持っている。

| | 本文 | 構造（島）の中 |
|---|---|---|
| モデル | `Editor`（`Vec<Vec<Item>>`） | `MathState`（ノードの木） |
| カーソル | `Sel`（複数・選択あり） | `Cursor`（1 つ・**選択なし**） |
| Undo | `Editor` の履歴 | `MathState` の独自履歴 |
| キー処理 | `on_keydown` | `keydown_in_math` |
| 保持形式 | アイテム列 | 本文には**記法文字列**として埋め込み、編集のたびに parse / 書き戻し |

`Session.active` の有無で「本文モード / 島モード」を切り替えており、
入力・カーソル・選択・Undo・IME・検索のすべてが二重化している。

これが「いちいち直感に反する」の根because:

- 島の中に**選択が存在しない** → 構造の中身をコピーできない、構造ごと選択もできない
- カーソルが二重（本文の位置＋島の中の位置）→ どちらが本物か揺れて、点線枠に入らない・入力中に枠から出る、という表示の不整合が出る
- IME の未確定文字は「本文のカーソル位置」に描かれる → 島の中で打つとずれる
- 検索・置換が島の中に届かない
- 修正するたびに二系統へ同じ処理を書くので、場当たり対応が増える

## 方針: エディタを 1 つにする

「書き味は普通のテキストエディタ」という目標に合わせて、
**本文と島を区別しないひとつの文書モデル・ひとつのカーソル・ひとつの入力系統**にする。

### 1. 文書モデルの統一

- `Item::Math { source: String }`（記法文字列の埋め込み）をやめ、
  構造ノードの木（今の `Node`）を文書がそのまま持つ。
- 記法（`$( ... )`）は**保存と読み込みのときだけ**現れる。編集中に parse / 書き戻しをしない。

### 2. カーソル・選択の統一

- 位置は「行 + 構造の中へのパス + オフセット」のひとつの型にする
  （今の `Pos` と `Cursor` の統合）。
- 選択は本文でも島の中でも同じ `Sel`。島の中の範囲選択・
  構造をまたぐ選択（構造は丸ごと 1 アイテムとして選択に入る）が自然に成立する。
- これで**構造の中身のコピー・構造ごとのコピー**が普通の Ctrl+C になる。

### 3. 入力系統の統一

- `active` によるモード分岐を廃止。キー → コマンド → モデル、の一系統。
- 「島の中だけの挙動」（Tab でスロット移動、Alt+Enter で行追加など）は
  モードではなく**カーソル位置の文脈**で決まるコマンドとして実装する。
- IME の未確定文字は常に実カーソル位置（島の中でも）に描く。

### 4. Undo の統一

- 履歴は文書に 1 本。島に入る・出るで履歴が切り替わらない。

### 5. 描画の統一

- 本文と島で描画器を分けず、文書の木をひとつのレンダラで描く。
  カーソル・選択・点線枠（空スロット）の表示が常に同じ規則になる。

## 進め方（PR の分割）

1. **モデル統合** — 文書が構造の木を直接持つ。保存/読み込みは既存記法のまま（ファイル互換は保つ）。
2. **カーソル・選択統合** — 位置型の統一、島の中の選択、構造をまたぐ選択。
3. **入力・IME・描画統合** — モード分岐の廃止、未確定文字の位置修正。
4. **これまで届かなかった機能** — 島の中のコピー/ペースト・検索置換の到達。

各段階で既存テスト＋追加テストを通し、ファイル形式は一切変えない。

## 変えないもの

- 保存されるテキスト（記法）と既存ファイルの互換性
- キー割り当て・パレット・タブ・分割などの外側の UI
- 「普通のテキストはただのテキスト」という原則
